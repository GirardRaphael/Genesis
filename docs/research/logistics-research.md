## Decision recommended to the lead

Use A11 as a **synthetic dispatch decision laboratory** for a dispatcher operating one depot, 3–5 vans and 25–50 stops. Compare an explicit baseline with a bounded solver candidate, simulate outcomes, expose violations and inspect the agents that produced the recommendation. These counts are deliberate scope assumptions, not a solver capacity claim. Start with parcel delivery and one demand unit, such as parcel slots; restaurant freshness, mixed vehicle classes and real fleet telemetry add different constraints and stay outside the first release.

The durable worker and observatory remain useful. Add OR-Tools as a typed deterministic optimization tool and MapLibre as the domain map renderer. Agents negotiate assumptions, coordinate tools, interpret evidence and handle exceptions. A language model must not invent stop orders, travel matrices, objective values or feasibility verdicts. A solver supplies candidate routes; an independent ordinary program checks them. Route calculations can be repeatable under pinned inputs/configuration without promising identical time-limited solver output on every machine.

The phrase “very high commercial potential” in the proposed topic is an unvalidated hypothesis. Commercial discovery must establish the current dispatch process, integration access, exception burden, achievable savings and willingness to pay. Subscription per vehicle and fees per tour are hypotheses until interviews and a pilot support one. This prototype does not establish road-operational suitability.

## Proposed domain and optimization contract

Each scenario artifact contains immutable IDs/hash, depot, vehicle IDs and capacities, shift bounds, stop coordinates, nonnegative integer demand, service duration, service-start window, required/optional flag, directed matrices, source/provenance, costs, simulation version and exception schedule. Use integer seconds and metres. Geographic points use `[longitude, latitude]`; reject reversed, nonfinite and out-of-area coordinates. Preserve asymmetry and unreachable edges; never replace null with zero. Round fractional routing values conservatively according to one declared rule before solving, and retain the raw source matrix for audit.

For stop j after i, proposed schedule semantics are `arrival_j = departure_i + travel_seconds[i,j]`, `service_start_j = max(arrival_j, window_open_j)`, `departure_j = service_start_j + service_seconds_j`. Windows constrain service start; this does not imply service completion must precede closing unless the scenario explicitly requires it. Depot departure and return must fit the shift. Show travel, service and waiting separately. Time dimension transit therefore includes service at the departure stop; service at the depot is explicitly defined.

For a pure depot-loaded delivery route, initial carried load is the sum of assigned delivery demands and remaining load decreases after each delivery. OR-Tools' cumulative demand dimension can constrain total assigned demand, but its cumulative values must not be mislabeled as physical remaining cargo. Capacity use is initial load/capacity; duty utilization is elapsed duty/shift length. Neither is a single interchangeable utilization score.

Initial planning enforces hard windows, capacities and shifts. The prototype reports simulation lateness when realized congestion differs from planning assumptions; it does not quietly relax hard constraints to improve a chart. A scenario that deliberately permits soft lateness must name that policy, penalty and distinction. Required visits remain required; optional visits carry explicit omission costs. “Valid with omitted optional stops,” “no validated candidate found,” “proven infeasible” and “invalid input” are different outcomes.

Choose one declared, versioned objective before comparing. The canonical choice enforces hard feasibility and minimizes estimated operational cost plus declared optional-stop penalties. Do not claim lexicographic service priority from an arbitrary large penalty. Integer minor-unit objective scaling, maximum magnitude and overflow checks belong in W01. Keep travel distance, wages, artificial penalties and fixed activation costs visible as components; they have different units until converted to a common objective unit. Solver objective is not automatically money or kilometres.

Canonical modeled operational cost is `distance_km × rate_per_km + duty_hours × rate_per_hour + active_vehicles × fixed_cost`; artificial omission penalties belong to the optimization objective and are excluded from spent operating cost. Rates are synthetic configuration, not invoices. Model-call spend has its own subtotal. Proposed emissions are `distance_km × explicitly configured kgCO2e_per_km`, labeled an estimate with factor provenance and boundary; do not invent a Canadian fleet emission factor, include unexplained life-cycle claims, or conflate route emissions with AI energy use. Revisit this model when an actual fleet/fuel dataset and applicable factor are obtained.

## Baseline, candidate and selection

Use the canonical deterministic nearest-feasible-next baseline with stop-ID tie breaking and the same declared constraints/cost function, including return-time checks. It must return routes plus explicit unserved/failed assignments, not quietly omit difficult visits. Run independent validation on baseline and optimized output alike. The candidate uses a pinned OR-Tools configuration and initial search budget of 20 seconds per search; benchmark in W01 and adjust transparently. “Optimized” means solver candidate, not certified global optimum.

Candidate adoption requires a validated assignment and cannot regress required-delivery coverage. Compare modeled cost only when service scope and constraints are equivalent, or clearly present the differing service results first. If the solver returns a worse candidate, retain a validated baseline where it is a valid incumbent under the same model; keep both outputs and the failed improvement visible. If baseline or candidate is invalid, suppress savings claims. Report `baseline=0` percentage savings as unavailable. A faster run that serves fewer required deliveries cannot count as successful improvement.

Do not optimize against data from the future: initial routing sees only the permitted initial forecast. The complete future event manifest and evaluation seed remain private to the deterministic simulator/test harness during execution. Every role prompt and tool receives only permitted forecasts and events revealed by simulated time; sealed manifest references must not expose future contents. Active endpoints and as-of replay enforce that boundary. Pair baseline and candidate against the same initial fleet/data and exogenous event IDs/times/effects; use immutable arc/time events or stable keyed random values rather than consuming one shared RNG in route order. Their evolved positions and reaction times can differ because their routes differ. Apply the same next-safe-boundary reaction rule and record each actual reaction time.

## Simulation and bounded exceptions

Start with one fixed directed forecast matrix per planning epoch and a saved realized directed matrix per simulation epoch. Applying multipliers to base durations is a **synthetic travel-time stress model**, not a calibrated city traffic model or road-network closure calculation. Generated multipliers never turn an unreachable road into a reachable one; bounds and units are validated. Serialize both matrices, event timing and seeds so offline replay never regenerates data or calls routing/model services.

Time advances through discrete stop/leg events. At an exception, preserve completed stops, the current leg and committed travel. Replan only at a documented safe stop-boundary checkpoint, using current vehicle locations, time, remaining cargo, completed ledger and unserved stops. The canonical flow allows at most one optimization-to-monitoring repair/replan cycle. If a vehicle is disabled with onboard cargo, those deliveries cannot be reassigned without a modeled transfer or return to depot. Defer transfer modeling; mark impacted stops unavailable and explain the service impact. A new order must be loaded at the depot by an eligible vehicle; it cannot appear on a van through reassignment alone. Include the frozen driven prefix once in cumulative distance and cost.

For healthy vehicles already traveling when an incident is assessed, the residual start is the next committed stop and its available time after committed travel/service. Do not fabricate an instantaneous new location. The stop-boundary outage is a declared simplification rather than a mid-road breakdown model.

The exception agent selects only allowlisted actions such as request one replan, retain prior validated schedule, or report insufficient capacity. The deterministic tool computes the consequences. On timeout/error, retain prior artifact history; never label an invalid or stale plan as current accepted. Each new candidate has a parent plan ID and scenario-state hash. Apply only if that state is still current; a stale optimization result cannot overwrite newer simulation state.

## Agent interaction and tool evidence

Retain the five named A11 roles as distinct bounded invocations: planning (course coordinator), simulated traffic (researcher), optimization (analyst), monitoring (verifier) and exception (exception handler). Planning emits a typed mission/constraint bundle; traffic emits a forecast artifact; optimization requests solver and submits candidate plus objective components; monitoring requests independent validation and simulation, then emits a verdict and alerts; exception assesses every run and emits no-action or a bounded action decision, returned to planning/optimization. Monitoring explains its independent certificate and cannot override a failed deterministic check. A separate development reviewer approves implementation changes; it is not a sixth application role.

Proposed distinct tools are scenario reader/traffic simulator, routing-matrix adapter, OR-Tools route solver and independent route validator/metric calculator. They remain fixed typed operations, not generated Python or shell. For the first live mission, record at least two genuinely distinct tool invocations and observable handoffs among at least four agents. A row labeled “traffic agent” around a bare deterministic callback does not alone establish an interacting AI agent. Record actual prompts/model IDs, typed outputs and the decisions delegated to each role.

Model routing: economy tier for bounded scenario extraction and structured forecast narration; standard for routine plan coordination and artifact explanation; stronger tier for exception tradeoffs and independent explanation verification. Arithmetic and constraint verdicts use checked programs. Actual available model IDs, prices and fallback evidence remain W01 work; this research executed no model benchmark.

## Independent validation acceptance

The validator consumes immutable input and candidate schedule, independently recomputes using matrix data, and does not trust solver cumulative values or reported totals. Shared schema/units are appropriate; independent computation must not call the solver's objective callback as its only check. Certificate scope is explicit: `initial_full_plan` covers the depot-to-depot initial plan; `residual_suffix` covers the future suffix from recorded checkpoint positions/available times/current cargo, including committed leg completion, to depot return. A residual certificate does not require a new initial depot departure or certify the already traveled prefix as on time. Historical lateness, violations and unrecoverable mandatory cargo failures remain immutable original-mission outcomes; a useful feasible suffix cannot erase them.

1. Every route references known IDs, starts/ends according to its initial or residual certificate scope, uses an available vehicle, and contains each served stop exactly once across the fleet/prefix-suffix partition.
2. Every required stop is served or the result explicitly fails required service; optional omissions reconcile against the complete stop manifest and penalties.
3. Every selected directed leg is reachable. Reported schedule matches travel, service and waiting; no negative duration or backwards time.
4. Initial demand and remaining physical load obey capacity; shifts/windows satisfy the declared hard policy. Replanning preserves completed/committed work and cargo location.
5. Distance, duty, operational cost, omissions, lateness and estimated emissions reconcile with detailed rows and component rates. Output units/rate versions are present.
6. Scenario, matrix, solver and validator versions/hashes match. Stale candidate adoption is rejected. Prefix plus suffix metrics count each driven leg once and retain prior violations.

Adversarial fixtures include duplicate stop, missing required stop, optional omission, oversized demand, zero demand, asymmetric matrix, unreachable edge, inconsistent arrival, omitted service/waiting, overtime return, false savings, expired matrix, solver timeout and cargo reassignment after breakdown. Add future-marker access denial for every role input/tool, unequal evolved states under the same exogenous schedule, and late/incomplete prefixes followed by valid residual suffixes whose full-day outcome remains late/incomplete. On tiny cases, independently enumerate permissible assignments/orders to check objective and constraint encoding; this proves those fixtures, not global optimality for 50 stops.

## Experiment and observatory acceptance

Canonical minimum is five scenarios × two logistics policies (`baseline_only`, `solver_with_one_replan`) × two paired saved seeds = **20 actual multiagent executions**. Every run includes all five agents; the baseline policy's exception emits a diagnostic without applying a replan. Saved fixtures and offline replay do not count as actual executions. Conditions are S01 nominal day, S02 clustered congestion snapshot, S03 tight/incompatible mandatory windows, S04 vehicle unavailable under a fixed incident schedule and S05 one new order under a fixed schedule. S04/S05 use the common next-safe-stop-boundary reaction rule, with per-policy actual reaction times recorded. Correct infeasibility handling is different from successful delivery service.

Hold model-tier policy fixed across the primary logistics-policy experiment. A model-tier ablation requires additional actual runs and an explicit secondary manifest; it is not part of the primary 20-run matrix. Pair logistics policies on the same saved input, exogenous realization and constraints; preserve failures and noncomparable pairs. Report sample counts, required-service rate, validated route rate, distance/duty/cost, optional omissions, simulated lateness, candidate rejection, solver/model latency, model usage coverage and all-in spend. Two seeds per cell support demonstration, not strong commercial generalization.

Retain all six required observatory views: agent graph, execution timeline, two-column observed-handoff Sankey, comparison chart, scenario × agent heatmap and overview KPIs. Add the route map as a seventh domain view; vehicle routes do not substitute for agent communication. Map and route table select the same vehicle/stop/artifact; plan, simulated actual and replay modes carry visible labels. Include baseline/candidate overlays, numbered stops, legend, direction and an accessible table with identical values. Map failure leaves readable route output and diagnostics available.

Attribution, provider terms, coordinate order, bounds, route geometry source, selected plan version and reduced-motion behavior are map acceptance checks. A straight line between stops must be labeled schematic; it is not road geometry or navigation guidance. Obtain a permitted local basemap dataset for offline delivery or use a disclosed coordinate schematic; never promise offline map tiles from a provider that prohibits caching.
